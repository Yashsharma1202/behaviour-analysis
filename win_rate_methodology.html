What the “win rate” means — and how the event is known in advance

This note documents, exactly as the code computes it, the win rate shown for Quarterly Results and Corporate Actions in the Rankings, Screener and Playbook — where the event date comes from, why you can act before it, the precise win-rate formula, how the “best rule” is chosen, and the honest limits of the number.

01The two events at a glance

EventDate usedSource fileHow you know it ahead of time
Quarterly Results
RESULTS		 broadCastDate <SYM>/financial_results.csv SEBI LODR Reg 29: the board meeting to approve results must be intimated to the exchange ≥ 5 clear days in advance.
Corporate Action
CORPORATE_ACTION		 exDate <SYM>/corporate_actions.csv The ex-date and record date are declared and broadcast by NSE days-to-weeks before they take effect.

The win rate is computed identically for both — only the anchor date differs. Everything in sections 3–5 applies to both events; the difference is purely which calendar date each event is pinned to.

02Why we can “predict” the event — it isn’t a guess

We never forecast that an event will happen from price action. We read the scheduled date off the regulatory calendar and position around a date that is already public. That is what makes a “buy N days before” rule actionable rather than hindsight.

Quarterly Results

The date is legally pre-announced

Under SEBI LODR Regulation 29, a listed company must notify the exchange of the board meeting that will consider financial results at least 5 clear working days beforehand. That intimation is public. So roughly a week ahead you already know “results are coming on/around this date” — which is your entry window.

Corporate Action

The ex-date is fixed in advance

When a board declares a dividend / bonus / split, the company fixes a record date and the exchange publishes the corresponding ex-date — typically two-plus weeks out. Files carry caBroadcastDate (when NSE announced it) well before exDate (when it takes effect), so the ex-date is known long before you must act.

03How one event becomes a set of trades

For a single event pinned to trading day T (the first trading day on/after the event date), we test every combination of an entry N days before and an exit M days after — with N = 1…8 and M = 1…8, i.e. an 8 × 8 = 64-cell grid of candidate rules:

entry price  = close at day  T − N  // buy N trading days before the event
exit price   = close at day  T + M  // sell M trading days after the event
return%     = ( exit / entry − 1 − cost ) × 100
outcome     = WIN if return% > 0  else  LOSS
  • Prices are daily adjusted close from Yahoo Finance (cached). “Days” are trading days (weekends/holidays skipped) — the code steps by index position, not calendar days.
  • cost is a round-trip cost fraction, currently 0 (gross returns). Set it to model brokerage/slippage.
  • Every historical event of that type on that stock produces its own 64 rows — one per (N, M) pair.

04The win-rate formula

We now pool all events of one type for the stock and, for each (N, M) cell, ask: across all those past events, what fraction made money?

win rate(N, M)  =   number of events where return% > 0  ÷  total number of events  × 100
avg return(N, M) =  mean of return% across those same events

So a win rate of 67% for “buy 3 before / sell 2 after” means: of all the stock’s past quarterly results, that specific rule closed green on two out of every three of them. It is a hit rate over historical events, not a probability of future profit (see §6).

05Choosing the single “best” rule that gets displayed

The dashboard shows one headline rule per stock-event. It is picked from the 64 cells like this:

1
Require enough events. Keep only cells backed by at least max(3, min(5, n)) events (≈ 5 when history is ample; all of them when a stock has very few) — so the headline rule isn’t built on one or two lucky quarters.
2
Prefer profitable rules. Among the survivors, restrict to cells whose average return is positive. If none are positive, fall back to the full set.
3
Rank by win rate, then average. Sort those by win rate first, breaking ties by average return. The top cell’s N, M, win rate and average become the displayed “buy N before / sell M after”.

Code path: event_behaviour.analyse_event → aggregate → build_behaviour (selection) → build_rankings (ordering). Same engine feeds the dashboard, the playbook, and the static site.

07What the win rate does not mean — read before trading

It is in-sample. The best (N, M) is chosen on the same events it is then scored on. That upward-biases the number — a rule picked from 64 tries will look good on the history that picked it, and will not repeat as cleanly out-of-sample. Treat it as a description of the past, not a forecast.
Corporate actions use adjusted close — the ex-date drop is already removed. Yahoo’s adjusted price back-adjusts for dividends/bonuses/splits, so the mechanical fall on the ex-date is not in the data. The corporate-action win rate therefore measures residual drift on a total-return basis, not “the stock recovering the dividend.” Do not read it as capturing the ex-date discount itself.
Small samples are noisy. A 100% win rate on 3 events is far weaker evidence than 60% on 30. Always read the win rate next to the event count shown beside it.
Results anchor on the broadcast day. broadCastDate is when the result actually hit the tape. The knowability argument rests on the separate Reg 29 board-meeting intimation preceding it by ~5 days; the return itself is measured around the broadcast day T.
