1Executive summary

This project studies how the 50 Nifty stocks move around their corporate events — quarterly results, board meetings, corporate actions and material announcements — to test one disciplined idea: buy a few days before a known, scheduled event and sell a few days after. For every stock and event type it brute-force tests 64 timing rules against the full event history, reports the best rule and its win rate, and serves everything through a self-built web dashboard.

The honest headline: past win-rates around events are real but in-sample and modest — a description of history, not a proven money machine. The project's value is the transparent, reproducible framework and the clean, verified, fully-historical Nifty 50 dataset behind it.

2Objective & core idea

2.1The question

Do Nifty 50 stocks show a repeatable price pattern around their corporate events — and if so, what is the best number of days to enter before and exit after each event type?

2.2The hypothesis: anticipation + drift

Because event dates are published in advance, markets partly anticipate them (price drifts up into a known results date) and partly digest them afterwards (price keeps drifting for days after the news). The strategy sits inside both windows.

Buy before

Catch the anticipation

Enter N days before to sit inside the run-up toward a date the market already knows.

Sell after

Catch the drift

Exit M days after so the post-event drift plays out instead of selling into the first spike.

Key framing. We never forecast whether an event happens — the date is read off the regulatory calendar. We only study the price behaviour around that fixed date.

6Methodology — the buy-before / sell-after trade

6.1The two-leg trade

For an event pinned to trading day T: buy N trading days before at the close, hold through the event, sell M trading days after at the close. You are never flat during the event.

Figure 6.1. One buy, one sell, held through the event.

6.2Anchoring & the 64-rule grid

T = the first trading day on/after the event date. We then test every combination of N = 1…8 days before and M = 1…8 days after — an 8 × 8 = 64-rule grid. Days are trading days (weekends/holidays skipped).

entry = close[T − N]  // N trading days before
exit  = close[T + M]  // M trading days after
return% = ( exit / entry − 1 ) × 100  →  WIN if > 0 else LOSS

6.3Worked calendar — “buy 3 before, sell 2 after”

Results broadcast on Thursday 24 July. Note the sell lands on Monday — trading days skip the weekend.

7The win-rate mathematics

7.1The formula

Pool all past events of a type; for each of the 64 cells, the win rate is the share that finished green:

win rate(N,M) = ( #events with return% > 0 ) ÷ ( total events ) × 100

7.3Choosing the one displayed rule

1
Require enough events — keep cells backed by ~5+ events.
2
Keep the profitable cells — average return must be positive.
3
Rank by win rate, then average return — the top cell becomes the displayed rule.

10Data-quality work

A
Merged the full history. The recent NSE export had truncated the financial-results history (e.g. Reliance to 4 quarters). Merging with the original archive recovered +2,860 unique event-dates — restoring 71–83 quarters per stock.
B
Fixed board-meeting duplication. The merge had doubled board meetings; de-duplicating to one row per date removed 617 duplicate rows (2.22× → 1.07×).
C
Backfilled board meetings 4×. NSE's feed holds only ~2 recent years; pulling historical "Outcome of Board Meeting" records from the announcements archive (to 2006) lifted the average from ~9 to ~38 meetings per stock.
Why win-rates dropped slightly after the merge (e.g. an announcement rule 61% → 57%): more events regress a flukey small-sample figure toward an honest one — lower but more trustworthy.

14On machine learning

The live system uses no machine learning — only grid search and statistics, deliberately, for full transparency. A standalone experiment (ml_model.py, scikit-learn) tested whether a model could predict the results trade using price + fundamental features. Its honest conclusion: with only ~48 training examples per stock, extra features hurt (curse of dimensionality) and the model could not reliably beat the trivial baseline ("always predict WIN" ≈ 62%). ML is therefore not part of the product.

15Limitations & findings

In-sample bias. The best (N,M) is chosen from 64 tries on the same history it is scored on, so win rates flatter. They describe the past, not forward probabilities.
Small samples. 100% on 1–3 events ≪ 60% on 30. Always read the win rate next to n.
Event overlap. Board meetings and results share dates where the meeting was the results approval.
Corporate actions ≠ dividend capture (adjusted-close, §8).
Overall finding. Under honest, market-adjusted testing, no robust, reliably tradeable edge survives out-of-sample on the Nifty 50. The project's worth is the transparent framework and the clean, verified, fully-historical dataset — a solid base for further, more careful research.
